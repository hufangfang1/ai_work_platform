# 老照片学习型重建试验

后续已执行实际高斯训练，见 [高斯训练记录](gaussian-training.md)。下文记录的是训练前的深度表面试验，保留作基线对照。

## 实际完成的内容

2026-09-23，在本机 Apple M1 Pro 上执行 VGGT-1B 相机与深度推理，将预测深度反投影为三维表面，并用原始照片纹理显示。入口为 `/neural.html`。可旋转、平移、前后移动，也可分照片检查错位。

这不是原照片覆盖层，不是已训练的高斯泼溅，也不是完整、准确的院子成品。默认使用三维整体视角，避免从原拍摄位置观看时掩盖几何误差。

10 张照片中有 9 张用于场景推理。`05-bird.jpg` 是局部鸟与砖墙特写，没有可确认的院落视角重叠，未强行加入。原始照片没有修改、没有上传到外部服务。

## 同一标准输入下的结果

输入尺寸均为 518 × 392；表面输出每两个像素采样一次。下表的支持比例只表示其他预测视角的深度与投影深度相差小于 5%，**不是还原准确率**。

| 照片组 | 照片数 | 有效采样点 | 三角面 | 跨视角深度支持 |
| --- | ---: | ---: | ---: | ---: |
| 正房与小棚 | 3 | 86,178 | 165,254 | 45.9% |
| 西厢房与大门 | 4 | 60,767 | 113,570 | 66.6% |
| 院内与大门 | 3 | 27,652 | 48,858 | 11.1% |
| 九张联合 | 9 | 138,735 | 256,243 | 43.4% |

低分辨率试跑的正房支持比例约 4.3%；换成 518 像素宽后为 45.9%。因此不能根据低分辨率试跑直接否定此方法。

## 目视检查

- 正房组从整体角度可看见立起的门窗墙面、前沿台阶和连续的局部地面，比传统 SfM 的 86 个点有实质进展。
- 小棚连接处仍有拉伸，人物和车辆遮挡留下缺口。
- 九张联合结果可以看见多个立面，但院内、树木及棚顶仍存在大面积拉伸和破碎，不能直接作为可自由漫游的成品发布。
- 照片拍摄位置下的颜色接近原图是纹理投影的结果，不能用来证明其他视角正确。
- 模型没有绝对米制尺度；照片未覆盖的区域仍未知。重复利用相似材料不等于恢复了真实结构。

显示过滤排除了低置信像素、深度跳变，以及保守矩形标记的人物/车辆区域。矩形遮挡也可能删去一部分真实建筑边缘。跨视角检查是对预测之间一致性的粗检，包含遮挡和重叠范围的影响，不能替代相机标定、特征重投影误差和人工测量。

## 可复现信息

- 上游：[facebookresearch/vggt](https://github.com/facebookresearch/vggt)，提交 `a288dd0f14786c93483e45524328726ab7b1b4ce`。
- 权重：[facebook/VGGT-1B/model.pt](https://huggingface.co/facebook/VGGT-1B)，5,026,874,952 字节；遵循上游权重许可。
- 本机原生 arm64 Python 3.11、PyTorch 2.7.1、torchvision 0.22.1，MPS。
- 聚合网络用 float16，相机和深度头用 float32；部分双三次插值由 PyTorch 回退 CPU。
- `prepare.py` 仅将初始化时的线性间隔张量放在 CPU，使 meta 初始化和 mmap 权重加载可用，未改变推理方程。
- 权重、预测 NPZ 和上游仓库位于被 git 忽略的 `artifacts/neural/`。网页所需导出数据位于 `public/neural-results/`。

已准备好权重与环境后：

```sh
.venv-neural/bin/python scripts/neural/prepare.py
.venv-neural/bin/python scripts/neural/infer.py --group main
.venv-neural/bin/python scripts/neural/infer.py --group west
.venv-neural/bin/python scripts/neural/infer.py --group yard
.venv-neural/bin/python scripts/neural/infer.py --group all
.venv-neural/bin/python scripts/neural/export.py
npm run dev
```

应串行运行推理，避免统一内存不足。每组输出 `summary.json`、`prediction.npz`，导出时生成 `validation.json`。页面可切换各组、单张预测表面、彩色点云和跨视角支持过滤。

## 对高斯泼溅路线的判断

这批数据已经比纯手工近似模型有更好的局部几何初始化，但联合场景仍存在明显错误。直接以这些错误相机和表面做高斯训练，可能只是把原视角拟合得更像，并不能保证漫游正确。下一项必要工作是对可靠的正房/西厢房局部进行特征匹配与相机优化，再确定能否统一尺度和连接；院内低支持区域仍需约束建模。当前未执行高斯优化，不把“能打开泼溅查看器”当作训练完成。

## 验证

`npm run build` 通过，三个 HTML 入口均进入构建。浏览器已查看正房整体视角与九张联合视角，未发现运行错误；整体视角明确保留了缺口和错位。构建仍有 Three.js 公共包大于 500 kB 的体积提示。

## 主模型照片表面迁移

`export_model_surface.py` 将 `main-0.json` 中保留的三角面和原始照片 UV 配准到正房墙面，输出 `public/neural-results/model-facade.json`。沿用门窗校准及西窗局部偏移，将表面约束到墙面平面，排除门窗、衣物和错位明显的门楣。没有填造原重建孔洞；原模型继续补底。边界透明度按采样网格距离羽化。

主场景 `neural-photo-facade` 使用同一张原照片和三角面拓扑，随“照片纹理”开关切换。此层保留照片已有光照，不接受第二次实时照明；因此相较于普通 PBR 材质，更接近原照，但动态光照适应有限。当前仅迁移正房部分墙面，不能视作全场景重建已融合。
