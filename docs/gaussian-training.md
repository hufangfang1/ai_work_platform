# 局部高斯重建实际训练

本轮已从深度表面展示推进到实际 3D Gaussian 参数优化。页面为 `/gaussian.html`，训练前对照仍在 `/neural.html`。不是把点云文件改成 `.ply` 后就称为训练。

## 流程

1. 以原照片的 VGGT 相机、深度和可信点初始化三维高斯。
2. 本机 Metal 前向渲染与反向传播，优化中心、各向异性尺度、旋转、不透明度和颜色。
3. 人物、车辆、时间戳的保守遮挡区域不参加图像损失；加入位置和尺度正则，降低稀疏视角下漂浮的风险。
4. 原始照片以 1036 × 784 输入颜色优化，几何初值来自 518 × 392 的深度预测。
5. 输出标准 INRIA PLY，通过 Spark 在浏览器中实际渲染高斯，可旋转、平移和键盘移动。

脚本：`scripts/neural/train_splats.py`。初次正房试跑使用 40,000 个高斯、1,200 步，耗时约 74 秒；三张训练图像的掩码区域 PSNR 从约 13–15 dB 升至 32–35 dB。**这些是参与训练的照片指标，不是未见视角的还原准确率。**

更高分辨率运行的精确步数、耗时和逐图指标保存在 `public/gaussian-results/main.json` 与 `west.json`，配套 `*-before-*.jpg`、`*-after-*.jpg` 为渲染对照。

```sh
.venv-neural/bin/python scripts/neural/train_splats.py --group main --steps 1800 --width 1036 --budget 80000
.venv-neural/bin/python scripts/neural/train_splats.py --group west --steps 1500 --width 1036 --budget 80000 --confidence-mask
```

采用 [metal-gauss](https://github.com/nandometzger/metal-gauss) 0.2.1 与 [Spark](https://github.com/sparkjsdev/spark) 2.2.0。本机指定现有 Command Line Tools 的编译器和 SDK 头文件，仅设置进程环境变量，没有改系统 Xcode 选择或接受系统许可。

## 相机优化的独立试验

`scripts/neural/refine_alignment.py` 使用已有的几何验证特征匹配和预测深度，优化各相机的刚体姿态和深度尺度。固定各连通分量的锚点，预留约 20% 的匹配点作为验证数据。

- 西厢房两张图的预留点双向投影偏差中位数由 6.15 px 降至 1.82 px。
- 大门冬夏两张图由 3.44 px 降至 0.63 px，但验证点仅 3 对，证据有限。
- 正房组三张由 7.45 px 升至 13.49 px，拒绝使用这次变差的优化。

结果保存在 `artifacts/neural/refined/`，完整日志为 `artifacts/neural/refinement.log`。高斯训练仍使用各局部组自身的 VGGT 坐标和相机，**未把联合组的局部修正与另一坐标系直接混用**。跨分量的连接没有被验证。

## 限制与视觉检查

第一版高斯在整体观察角度下，正房门窗和台阶表面较三角网格连续，局部颜色与原照更接近。但这并没有恢复所有缺失内容：前景地面有模糊和漂浮，小棚连接仍有变形，屋顶和遮挡区域不完整。训练视角拟合好不能证明整个院子几何正确。

默认展示整体三维视角；可切换到原拍摄位置核对，不能只靠原视角截图验收。页面标注了局部结果状态，不将尚未连通的正房与西厢房硬拼成完整漫游场景。


## 第二轮修正

西厢房首轮未限制低置信天空区域，出现明显白色漂浮块，因此重新训练时加入 `--confidence-mask`，并依据两张西厢房原照片的屋顶轮廓排除上方天空。两轮损失掩码不同，不能直接将指标升高算作同条件质量提升。

修复了预览相机切换问题：更改相机上方向后重新建立 OrbitControls，避免沿用上一个视角的轨道坐标系。这同时应用于深度预览与高斯预览，已验证正门原拍摄位置能够正确显示。

页面仍将正房和西厢房分开展示，不能把尚未验证的整院连接当作已经解决。

最终运行：正房 80,000 个高斯、1,800 步、142.3 秒；西厢房 80,000 个高斯、1,500 步、97.6 秒。西厢房重新训练后，整体视角上方的大面积白色浮块消失，仍可见建筑缺口，未用白色表面掩盖缺失。浏览器两组均能载入，无运行错误。页面根据实际可见高斯范围取景，生产构建通过；Spark 独立入口有较大的包体提示。

## 与完整几何模型融合

主入口 `/` 现已默认接入正房墙面的训练高斯细节，控制栏“高斯细节”可单独切换。Spark 与原场景共用 Three.js 渲染器、相机和深度缓冲，细节挂在房屋组下，沿用房屋的位置、旋转和横向缩放。

`scripts/neural/build_hybrid_details.py` 从实际训练的 `main.ply` 筛选 4,311 个高斯；根据原照门窗标记建立平面配准，传播投影协方差，压平至修正后的墙面。位置拟合均方根约 0.057 个房屋局部坐标单位，非实测精度。排除窗洞、门洞、衣物区域、大深度误差与颜色不一致的高斯，限制足迹、降低透明度并羽化边缘。颜色按主场景的线性颜色流程转换，避免初次融合出现的过亮斑块。

这是“几何约束的训练高斯细节层”，并非把完整高斯场景未经修正地放进院子。当前只覆盖正房局部灰墙，不宣称屋顶、院内地面或西厢房已经融合。核对了有限数值、墙面高度偏移和门窗中心排除，93 项已有测试通过。
