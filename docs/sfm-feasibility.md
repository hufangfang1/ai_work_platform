# 十张老照片的稀疏三维重建试验

## 实测结论

完成了十张照片、全部 45 对组合的匹配，并完成 7 组重建配置。当前最好结果为 **4 张照片、86 个三维点，其中 71 点有至少 3 张照片共同支持**。恢复的是西厢房 / 大门附近局部立面线索，**没有恢复完整院子，也没有恢复可用的地面表面**。

这比两图片段更有依据，但仍不足以直接生成完整、可自由漫游的写实高斯场景。没有进行高斯训练，也没有拿现有手工模型冒充扫描结果。

[本地交互检查页](http://127.0.0.1:6174/reconstruction.html)：可旋转点云、查看相机位置、筛选三图支持点，并查看每张照片中实际参与重建的位置。

## 方法与参数

- 十张原始 JPEG 按 SHA-256 核对，没有重复；全部缺少可读取的相机、焦距 EXIF。
- CPU 本地计算，不上传原照。
- PyCOLMAP 3.12.5 在本机的 JPEG 解码阶段出现 `BITMAP_ERROR`，因此改由 OpenCV 读取与提取 SIFT，转换成 RootSIFT 描述子，导入 COLMAP 数据库。未把该兼容问题算作重建失败。
- 图像特征提取最长边 2400 像素，每图最多约 12000 特征；原照不改写。
- 每张照片独立 SIMPLE_RADIAL 相机；无实测焦距，默认初值为最长边的 1.2 倍。
- 穷举匹配及引导匹配、几何验证。引导匹配可能增加对应点，因此几何内点数可能大于第一轮 raw 匹配数。
- 原照 45 对中 18 对有几何内点；排除遮挡后为 9 对。内点多不等于能完成三维初始化。
- 对照遮罩为手工估计的保守矩形，排除人物、车辆、日期，可能同时遮掉一部分背景；原照基线用于对照这种影响。
- 初始化敏感性试验将最小初始三角化角从 16° 调至 8°、初始最少内点由 100 调至 60；新相机定位仍保留 30 内点要求、常规重投影过滤。
- 正房的两次定向初始化进一步尝试 4° 初始角，仍未得到模型。
- 当前点云尺度和朝向由重建自行确定，尚未与院子模型或实际米制尺寸配准。

## 文件与复现

环境在项目忽略目录 `.venv-sfm/`，完整数据库、日志、原照副本、COLMAP 文本 / 二进制模型与 PLY 在 `artifacts/sfm/`。原照片仍在 `public/home-photos/`。

```sh
.venv-sfm/bin/python scripts/sfm/reconstruct.py --run opencv-baseline
.venv-sfm/bin/python scripts/sfm/reconstruct.py --run static-mask --masked
.venv-sfm/bin/python scripts/sfm/retry_mapping.py
.venv-sfm/bin/python scripts/sfm/retry_facade.py
.venv-sfm/bin/python scripts/sfm/export_preview.py
npm run dev
```

预览数据：`public/sfm-results/reconstruction.json`。结果页单独位于 `reconstruction.html`，当前通过 Vite 开发服务器访问，不替换院子主页。

## 下一步判断

这次验证说明：常规 SIFT / COLMAP 在这十张照片上只能得到局部片段，尚未得到高斯重建需要的完整相机覆盖。它不证明所有稀疏照片方法都无效。下一次有意义的实验是学习型跨视角匹配或稀疏视图几何方法，优先验证正房和地面的跨图对应；仍需用实际观测检验，不能把 AI 补出的区域当作实物证据。此时直接训练高斯或继续全局改地面颜色，不能解决缺少共同几何约束的问题。

工具依据：[COLMAP 官方教程](https://colmap.github.io/tutorial)、[PyCOLMAP 官方接口](https://colmap.github.io/pycolmap/index.html)。
