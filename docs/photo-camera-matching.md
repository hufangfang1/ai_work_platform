# 正房原照相机匹配：诊断阶段

进入页面右上角“原照对齐”，滑动透明度查看现有模型与原照片的重叠。固定 4:3 画幅，允许相机横滚；退出后恢复正常漫游视角。

取样：原图 `public/home-photos/01-house.jpg` 的十处窗台、窗横档、门洞及侧窗边界。人工标记坐标、拟合相机、各点误差保存在 `src/scene/photoCameraFit.json`。使用 `python3 scripts/fit-photo-camera.py` 可复算，需要 NumPy。

当前保持模型尺寸不变，只拟合相机。约 19.2 像素 RMS 是这些人工标记点的拟合残差，不是三维测量误差。焦距达到下限 350 像素，得到约 114 度竖直视场；这是一项异常诊断结果，不能据此认定原照片真的使用这种镜头。需复核对应点、几何比例及主点假设，再约束焦距与相机位置。

叠加中能看出门前台阶的前缘、深度与原照明显不合，晾挂物的位置也有偏差。但结构与相机参数耦合，当前不根据一次拟合直接改全屋尺寸。下一步以第二张正房参考照交叉约束窗框与门洞，先统一相机与立面比例，再修正台阶进深。现有用户确认的红绳系点继续保留。

本阶段没有自动摄影测量、没有完成精确标定，也没有对原照片做生成补画。

## 2026-09-24：按 neural.html 的三维数据校准门窗

使用 `artifacts/neural/main/prediction.npz` 中的正房第一视角，对已有照片角点取 5×5 邻域中值。门头左右点建立横轴，门头与门脚建立正交竖轴；仍以暂定的门头 3.05、门口平台 0.28 为尺度锚点，并将重建中略歪的门窗归正。不是直接使用高斯的包围盒，也不是按截图透视宽度缩放。

可复现脚本：`scripts/neural/calibrate_openings.py`；参数：`src/scene/neuralOpeningFit.json`。正房门中心维持在双坡道中线，调整门宽、左右边窗偏移、左大窗中心与宽度、窗台及横档高度。未在照片中完整出现的窗顶保留原值；另一侧大窗的位置和宽度没有足够证据，暂未重定位，仅共用水平窗台和横档基准。

模型 X 轴原有 0.8 缩放：门扇总宽约由 1.72 改为 1.87，左大窗宽约由 2.46 改为 2.34，窗中心向外移约 0.11；窗台由 1.575 改为 1.487，横档由 2.955 改为 2.781。单位沿用模型暂定米制，不代表现场实测。

墙洞、窗框、玻璃、晾衣绳端点使用共享布局参数。重新拟合诊断相机并重新导出正房高斯墙面细节，防止旧避让范围覆盖新门窗；相机角点 RMS 由 9.56 px 变为 8.70 px，这仅是所用标记的拟合误差。93 项测试和生产构建通过，浏览器无运行错误。

## 西侧墙角定位修正

上述门窗比例拟合尚未约束西厢房与正房的内侧交接墙角。原模型左大窗西边缘到西厢房内墙仅约 0.497 米；01-house.jpg 中约 (125, 350) 的墙角，经既有立面映射得到局部 X 约 -6.97，而实际模型交接点为 -5.875。因此将已校准的门窗组整体偏移局部 X +1.10（世界方向向东约 0.88 米），窗侧空白墙宽变为约 1.377 米。这是照片估计，不是实测；门窗相对间距保持不变，未测定的另一侧大窗不参与本次平移。

双坡道继续以门中心对称，绳端、晾挂物、保温瓶、高斯细节的避让区及照片相机同步更新。相机标记 RMS 仍约 8.70 px；纯平移并不会降低该残差，不能把它当作新增精度证明。新增西墙净距回归检查，94 项测试及生产构建通过，浏览器未发现运行错误。

## 正门东侧间距回归修正（覆盖上节整体平移）

用户指出整体平移使正门东侧关系失真。撤销门中心的 +1.10 局部偏移，门中心恢复 1.725，双坡道和门侧绳端随门恢复；西侧大窗保留局部修正，东侧窗和小棚固定。高斯细节改用原立面配准加局部横向映射：西窗区域平移，窗与门之间连续过渡，到门侧归零，避免把东侧细节一起挪动。

这项局部修正使单相机全立面的角点拟合残差升至约 33.21 px，焦距达到约束下限，说明当前局部几何约束仍不完全一致。原照对齐仅作诊断，不能据此声称整体比例已准确还原。后续应联合墙角、门窗及小棚边界校准，而非再次整体平移门窗。
